# RehabMed · P1 真機手工驗收清單（Device Checklist）

> 對應 `docs/p1_spec.md` §16 驗收標準中**平台依賴 / 需視覺確認**的部分。
> 沙箱無法自動化的項目，在具備真機或模擬器時按此清單逐項過一遍（約 10 分鐘）。
> 已自動化覆蓋的部分見 `test/`（`flutter test` 全綠），不需重複人工驗證。

## 前置
- 環境：Windows 桌面 / Android 模擬器 / 實機（任選其一，建議 Android 實機覆蓋最全）
- 命令：`flutter run`（沙箱外正常環境；沙箱內僅能 analyze/test，無法跑 UI）
- 登入：醫生帳號（任意 ≥6 位密碼）→ `/doctor`；患者 → `/patient`

---

## 1. 生物辨識安全鎖（P1-7，#13）— 需真機
- [ ] 登入後將 App 切到後台，等待超過設定逾時（設定頁可改 1/3/5/10 分鐘），再切回前台 → 出現鎖屏「應用已鎖定」
- [ ] 生物辨識（指紋 / Face ID）驗證成功 → 解鎖回到原頁面（路由棧保留）
- [ ] 生物辨識失敗或平台不支援 → 顯示密碼兜底輸入框，輸入 ≥6 位密碼可解鎖
- [ ] 逾時內（如 1 分鐘）切回前台 → 不鎖
- [ ] 設定頁關閉「啟用安全鎖」→ 切回前台不再鎖
- ⚠️ Windows 桌面若無生物辨識裝置，會走密碼兜底分支（可驗證 fallback UI）

## 2. 本機通知（P1-5，#7）— 需真機 / 平台
- [ ] 匯入完成後收到本機通知（匯入成功事件）
- [ ] 通知權限被拒時 App 不崩潰（main 已 try/catch 平台未配置）
- ⚠️ 通知在 web 不支持；Android 需 POST_NOTIFICATIONS 權限（13+）

## 3. 檔案匯入（P1-3，#11）— 需真機
- [ ] 點「匯入」→ 系統檔案選擇器彈出
- [ ] 選取範例 JSON（可用 demo 種子同構的 JSON）→ 解析成功 → 患者入列
- [ ] 選取非法 JSON / 缺欄位 → 顯示匯入校驗錯誤，不崩潰

## 4. 視覺 / 主題（P1-9，#9 與 P1-8，#10）— 需目視
- [ ] 醫生登入 → 藍色系；患者登入 → 青綠色系（角色感知）
- [ ] 設定頁切換 淺色 / 深色 / 跟隨系統 → 全 App 即時生效
- [ ] 開啟長者模式 → 字號明顯放大（滑桿 1.0–2.0× 即時生效）
- [ ] 開啟高對比 → 背景純白/純黑、文字對比增強
- [ ] 開啟簡化導航 → 醫生首頁只留 設定/登出，匯入/載入範例隱藏
- [ ] 系統字體設為特大（≥1.3×）→ 長者模式自動開啟（開關顯示 ON）

## 5. 既有 P1 冒煙（可快速目視）
- [ ] 登入 → 醫生首頁患者列表 + 右側 data-driven 儀表板（gauge/折線/柱/雷達依指標切換）
- [ ] 「載入範例」→ 看板出圖；殺掉 App 重開 → 資料仍在（Hive 持久化，自動化已驗）
- [ ] 軟刪患者（若有入口）→ 列表消失、審計可查（自動化已驗）
